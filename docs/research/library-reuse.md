# Library reuse for the RUF bulletin web application

Research snapshot: 2026-11-10. This is a buy-vs-build assessment, **not** an implementation or a final stack decision. [PRODUCT.md](../../PRODUCT.md) and [EDITOR.md](../design/EDITOR.md) govern behavior; the prototype's localStorage and print approximation do not. The working tree already contains an in-progress Bun workspace: React frontend, Elysia server, Drizzle + `pg` connection, and `@ruf/generator` using PDFKit ([packages](../../package.json), [server](../../packages/server/package.json), [frontend](../../packages/frontend/package.json), [generator](../../packages/generator/package.json)). The server presently exposes only health and a shell; `/mcp` is explicitly unimplemented ([app.ts](../../packages/server/src/app.ts)). Recommendations below do not assume that these uncommitted changes are finished.

## Short answer

Reuse the existing generator and stack; **buy plumbing, build the bulletin semantics**. Highest-value additions are a maintained authentication library, the official MCP TypeScript SDK, and (only if drag interactions are wanted) a sortable-list library. Elysia already supplies API validation/upload parsing; Drizzle supplies database access and migrations. Do not introduce a CMS, generic page builder, separate object-storage service, OAuth server, or a second PDF renderer just to get started. The remaining bespoke work is the authoritative bulletin/song/asset model, invitation redemption, ordered editing semantics, generation adapter/errors, and revision-aware saves.

### If “lazy” includes replacing the chosen architecture

There is a higher-level alternative worth an explicit decision rather than silently ruling it out: [Payload](https://payloadcms.com/docs/getting-started/what-is-payload) supplies a generated admin UI, auth, access control, CRUD APIs, migrations, and uploads; its [Postgres adapter](https://payloadcms.com/docs/database/postgres) uses Drizzle and `pg`. It could replace substantial portions of the Elysia API, custom React editor, and auth plumbing. The price is adopting its **Next.js full-stack application and generated admin model**, not just importing a function into the agreed Bun-built React/Elysia server. The document-first editor, exact invitation policy, broken song-key semantics, revision conflicts, PDF generation and MCP tools would still need integration or custom UI. A short spike might be worthwhile *only if* the four-package/Bun/Elysia design is negotiable.

[Directus](https://directus.io/docs/api) is another higher-level self-hosted option with generated REST/GraphQL interfaces and a data studio on Postgres ([requirements](https://directus.io/docs/self-hosting/requirements)). It entails an additional service and its [default upload storage is filesystem or external](https://directus.io/docs/configuration/files), contrary to the confirmed one-Bun-service and image-bytes-in-Postgres direction. Do not mistake either platform's generic CRUD screens for a validated substitute for the folded-bulletin editor. Neither alternative is a drop-in dependency under the currently agreed architecture.

Avoid that plugin's organization/team model for this one-organization app. Implement code issuance, hash-at-rest, atomic redemption tied to successful account creation, and no public sign-up bypass. | MCP transport / tools / keys | **Official TypeScript MCP SDK v2**, medium integration: current split [`@modelcontextprotocol/server`](https://github.com/modelcontextprotocol/typescript-sdk/blob/main/README.md) documents Bun support, tools with schemas, and Streamable HTTP; [2026-07-28 Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) requires an HTTP **POST** endpoint and `Origin` validation (the old standalone GET stream was removed in this revision). No first-party Elysia middleware is listed; adapt its Web Request/Response transport or mount via a thin handler and test under Bun. [Better Auth API-key plugin](https://www.better-auth.com/docs/plugins/api-key) can generate/verify/revoke multiple user-owned keys; **medium** integration because its normal create/list/delete endpoints are owner-facing, while RUF admins must manage keys for *named other staff*. Server-side creation supports `userId`; verify admin-only listing/revocation behavior or use a small dedicated key table instead. | Put key verification and identity resolution *before* MCP processing; never expose account/invitation tools. Register bulletin/song/asset CRUD and PDF generation against the **same application services** as HTTP. Pass expected revisions for MCP mutations too, and return actionable tool errors. A manually provisioned API key in `Authorization` is **not** OAuth: the [MCP HTTP authorization spec](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) describes OAuth discovery/audience-bound tokens when that authorization mechanism is supported. API-key-only clients must be explicitly configured and tested for interoperability; do not claim OAuth compliance or build an OAuth server without a client requirement. |
| SPA routing / fetching / API | **Start small**: React is already installed. [TanStack Router](https://tanstack.com/router/latest/docs/framework/react/overview) adds typed routes/loaders; [TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview) adds server-state caching/invalidation. For four or five screens, add only when URL navigation/load/error complexity merits it; Router's own loader cache can suffice before Query. [Elysia Eden Treaty](https://elysiajs.com/eden/treaty/overview.html) can infer a client from an exported server type, reducing DTO duplication; evaluate against simple `fetch` before coupling the frontend to server types. | HTTP endpoints/auth gates/error contracts, unique-date creation, search, confirmation, unsaved edit preservation, and explicit `409` conflict UI. Client caches **cannot** enforce concurrency. Make bulletin save a conditional `UPDATE … WHERE id = ? AND revision = ? RETURNING …` and persist changed composition atomically in one DB transaction; zero rows => conflict with newer revision. Keep the submitted draft available to compare/recover, never auto-overwrite it. |

## Bun / version checks before adopting packages

- Bun aims for Node compatibility but documents differences in `node:stream`, `node:crypto`, `node:async_hooks` and other APIs ([Bun compatibility matrix](https://bun.sh/docs/runtime/nodejs-apis)). Execute an end-to-end spike for Better Auth + its Drizzle adapter + `pg` under the repository's actual Bun version, especially session cookies, password hashing, migration CLI and registration transactions; package docs do **not** prove this exact combination works. Test PDFKit streams/images under Bun as well as browser-served PDFs.
- MCP SDK `main` is **v2** (`@modelcontextprotocol/server`); the older `@modelcontextprotocol/sdk` is **v1** on a separate branch ([official README](https://github.com/modelcontextprotocol/typescript-sdk/blob/main/README.md)). Pin and test one SDK/protocol generation rather than copying a v1 transport example into v2. The current MCP specification is dated 2026-07-28; older 2025 examples may have different authorization/discovery details.
- Drizzle's public docs also discuss a v1 beta while this workspace declares `drizzle-orm ^0.44.0`. Pin compatible `drizzle-kit`, auth adapter and driver versions after testing; do not treat a documentation example for a newer major as proof of compatibility with the checked-in lockfile ([Drizzle migrations](https://orm.drizzle.team/docs/migrations), [Better Auth adapter](https://www.better-auth.com/docs/adapters/drizzle)).

**Decision sequence:** (1) keep existing packages; prototype a domain-shaped save/generate boundary, (2) spike Better Auth registration/invitation atomicity and admin-owned key administration, (3) spike SDK v2 at `/mcp` with one authenticated tool and Elysia `Origin` handling, (4) add DnD/forms/router/cache packages only when the editor's real interaction code needs them. These are recommendations, not commitments to deferred email or hosting choices.
